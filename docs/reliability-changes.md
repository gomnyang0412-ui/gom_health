# 요청과 요약의 신뢰성 개선

## 적용 범위

- 동일 request ID의 재전송은 상태/최종 응답 조회로 처리한다. 같은 문장의 새 ID는 별도 운동이다.
- 접수 시 requests와 원문 messages를 한 트랜잭션에 저장한다. 최종 운동·응답·상태도 함께 커밋한다.
- processing 기한은 90초다. 기한 초과는 다음 앱 조회/요청 조회 시 failed로 전환한다. 백그라운드 스케줄러는 없다.
- 처리 중 원문은 직접 복구 대상에서 제외한다. 만료된 작업은 write transaction 안에서 상태를 확인하므로 뒤늦게 저장할 수 없다.
- 브라우저는 미확인 채팅 요청을 sessionStorage에 보관한다. 처리 확인·재전송은 같은 ID를 사용하며, 확정 뒤 새 입력은 새 ID를 만든다. DB 접속 실패는 저장 성공으로 표시하지 않는다.
- 근력·맨몸의 시간 필드, 유산소의 무게·횟수·세트를 양방향 검증한다. 잘못된 AI 결과는 부분 저장이나 수치 보정 없이 미기록으로 남긴다.
- 운동명은 공백·대소문자 정규화와 보수적인 AI 프롬프트를 사용한다. 명확히 같은 이름만 재사용하고, 실제 저장한 이름/수치를 확인 메시지에 표시한다. 기존 운동 일괄 병합은 없다.
- 날짜별 마지막 요약 메시지만 표시한다. 기존 요약 메시지는 삭제하지 않는다.
- 수정·삭제 및 추가 기록은 날짜의 변경 버전을 증가시키고 이전 피드백을 무효화한다. 수정·삭제 후 '기록이 수정되어 수치가 갱신되었습니다.'를 표시한다. 다시 끝을 보내야 AI 피드백이 생성된다.
- 피드백 생성 중 날짜의 변경 버전이 바뀌면 오래된 피드백을 저장하지 않는다.

## 운영 DB에 적용되는 변경

앱의 첫 DB 초기화에서 `lib/migrate.ts`가 트랜잭션으로 추가 필드를 생성한다. 기존 exercises/logs 행은 수정하거나 삭제하지 않는다.

requests에 status, kind, message_id, expires_at, completed_at, error_code를 추가한다. 응답이 없는 이전 요청은 자동 재실행하지 않고 failed로 분류한다. 이전 요청의 메시지는 원문/날짜/시각이 유일하게 일치할 때만 연결하며, 연결되지 않은 실패 원문은 복구용 메시지로 보존한다. 이전 직접 기록 요청은 입력 본문을 보관하지 않았으므로 같은 ID가 들어오면 재실행 대신 충돌로 처리한다.

날짜별 version과 feedback_state를 저장하는 day_state 테이블을 추가한다. 기존 요약/운동 기록을 소급 병합하거나 삭제하지 않는다. 이 마이그레이션은 별도 레거시 테스트 DB에서 두 번 적용해 검증했다.

GitHub 운영 브랜치 푸시는 연결된 Vercel 자동 배포를 유발할 수 있다. 이전 앱과 새 앱을 동시에 직접 사용하기보다는 새 배포가 준비된 뒤 새로고침한다. 기존 프로세스가 이미 처리 중이던 구버전 요청에는 새 요청 상태 보장이 소급 적용되지 않는다.

## 검증 기록

- 별도 임시 SQLite DB: 요청 재전송/동시 처리, 실패 시 롤백, 원문 보존, 만료 작업 차단, 직접 기록 복구, 날짜 분리, 요약 중복 제거, 수정/삭제/피드백 경쟁, 레거시 마이그레이션.
- 가짜 Gemini 응답: 429 폴백, 비할당량 오류, 잘못된 구조, 복수 결과 전체 검증 실패. 실제 Gemini의 자연어 동의어 판별 정확도는 이번 테스트로 검증하지 않았다.
- 로컬 브라우저: 독립 임시 DB로 127.0.0.1:3100을 실행. 동일 문장 두 번 입력 → 400kg/2세트, 끝 두 번 → 요약 한 개, 한 기록 30kg 수정 → 500kg, 그 기록 삭제 → 200kg/1세트, 채팅과 달력의 갱신 문구를 확인했다. 새로고침 후 보관된 요청 재전송도 확인했다.
- 운영 Turso 및 운영 배포 주소에서 변경 테스트를 하지 않았다. 실제 모바일 기기와 실서비스 AI 호출은 이번 검증 범위에 포함하지 않았다.

타입 검사와 프로덕션 빌드도 실행한다. 테스트는 원격 URL 또는 인증 토큰이 있는 테스트 DB 구성을 차단하며, 운영 환경변수를 읽어 테스트를 수행하지 않는다.
